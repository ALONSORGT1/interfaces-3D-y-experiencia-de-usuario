# Comprobación de R2 y R4

## R2 · Cargar escenario y/o personaje mediante GLTFLoader

**Implementado en la primera versión y conservado en la ampliación.** La primera versión cargaba `office.glb` y `employee.glb`. La campaña actual carga:

| Archivo | Uso real |
| --- | --- |
| `assets/models/campus.glb` | Escenario principal de 100 × 54, con materiales y textura de alfombra incrustada |
| `assets/models/employee.glb` | Modelo del jugador y base de los personajes de la campaña |

En `assets/js/scene.js`:

```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
const loader = new GLTFLoader();
// Dentro de la carga inicial de recursos:
loader.loadAsync('./assets/models/campus.glb');
loader.loadAsync('./assets/models/employee.glb');
```

Los modelos se añaden a la escena y se utilizan en el juego. El campus se agrupa por material **después** de cargarlo: es una optimización de los datos obtenidos del GLB, no un escenario alternativo que evite el requisito.

Para comprobarlo manualmente, abre Network, filtra por `.glb` y recarga. Deben verse las dos solicitudes correctas. Si se elimina o renombra uno de estos recursos, la carga falla y aparece el mensaje de reintento; los archivos no están incluidos solo como adorno.

## R4 · Cuatro estados reales gestionados por AnimationMixer

El JSON interno del GLB `employee.glb` contiene cuatro entradas en `animations`:

| Clip del archivo | Acción del usuario | Reproducción |
| --- | --- | --- |
| `Idle` | Dejar de moverse | Bucle de reposo |
| `Walk` | WASD / flechas | Ciclo de caminar |
| `Run` | Shift + movimiento | Ciclo de correr |
| `Throw` | F / espacio / LANZAR, o empujar con E | Lanzamiento de una ejecución |

En `assets/js/character.js` se construye `new THREE.AnimationMixer(this.model)`. Cada clip del recurso cargado se registra con `mixer.clipAction(clip)`. `animate()` hace las transiciones con `crossFadeTo`; `step()` decide Idle/Walk/Run y actualiza el mezclador con `mixer.update(dt)`. `throw()` activa Throw durante la acción, y `LoopOnce` evita que el lanzamiento se repita indefinidamente.

Las animaciones utilizan nodos articulados del GLB: torso, brazos y piernas. Un rig con skinning no es necesario para el requisito de cuatro estados/clips. Los NPC también tienen mezcladores independientes.

## Evidencia automatizada

`tests/smoke.cjs` comprueba:

- Que el escenario GLB produce mallas en el mundo.
- Que los clips cargados son exactamente Idle, Walk, Run y Throw.
- Que el controlador usa una instancia real de AnimationMixer.
- Que las teclas de movimiento activan Walk y Run y al soltarlas vuelve Idle.
- Que un lanzamiento activa Throw y produce una bola que derriba objetos físicos.

El resultado se conserva en `docs/verificacion.json`. Para observarlo en persona, inicia la campaña, camina, corre y lanza; las cuatro acciones se pueden distinguir en el personaje.
